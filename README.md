# Enterprise Finance GenAI Assistant

A finance investigator over three systems of record: it answers **why a payment is unmatched** or
**why a settlement is delayed or flagged** from their data, with citations, separating what a record
states from what is inferred; it **proposes** a write-off or refund within policy; and it **executes**
an adjustment only after **a second person approves**, exactly once.

> **Reference implementation, not a production service.** Synthetic data only (tenant `acme`); it
> runs on the Google Cloud free tier with Gemini's free tier. See [SECURITY.md](SECURITY.md).

It is the fourth application of a landscape built on the [E2A](https://github.com/subhamviky/e2a-framework)
contracts (hub design note GCP-01) and depends on the other three:

| System | Repository | What the assistant reads or writes |
|---|---|---|
| reconciliation-service | [payment-reconciliation-engine](https://github.com/subhamviky/payment-reconciliation-engine) | open exceptions of bank lines (read) |
| settlement-service | [financial-settlement-platform](https://github.com/subhamviky/financial-settlement-platform) | settlements, their events, the adjustment ledger (read; the one write) |
| audit-ai-service | [financial-settlement-platform](https://github.com/subhamviky/financial-settlement-platform) | audit findings per settlement (read) |
| o2c-agent-service | [order-to-cash-agentic-ai](https://github.com/subhamviky/order-to-cash-agentic-ai) | orders (read) |

## How it works

```
caller (Google ID token) ─▶ genai-assistant-service (Cloud Run, IAM-protected)
  route    IntentAgent        model: investigate | explain | propose; identifiers only if the request states them
  gather   EvidenceAgent      reads the four systems through io_read; each fact gets an id (recon:…, settlement:…)
  reason   InvestigatorAgent  model: a grounded answer; every citation must be an id that was read
           ProposalAgent      model drafts; policy decides (limit, currency, COMPLETED, ≤ settlement amount)
  execute  ExecutionAgent     pauses for a second person (approver role, four eyes); then posts once, reads back
```

The model is bound from `E2A_PROVIDER_PROFILE`: `simulated` by default (no account, no network), or
`gemini_api` (the Gemini Developer API's free tier). When the model is down or answers badly, every
model step has a deterministic fallback: the verified facts alone, or no proposal. Nothing executes
without a valid proposal and an approval.

## Generated, then completed

The service was generated by [A2C](https://github.com/subhamviky/a2c-framework) `aidlc-build` from
[`aidlc/request.json`](aidlc/request.json) (agents, workflow, governance stages, evaluation sets, release
gate, Terraform, CI); the untouched scaffold is on the branch `aidlc/genai-assistant-service`. `main`
completes it by hand: the tools, the agents' prompts, checks and fallbacks, the approval workflow, the
stand-ins and the evaluation cases.

## Run and test

```bash
cd genai-assistant-service
poetry install
poetry run pytest -q
poetry run python -m genai_assistant_service.release.gate --skip-tests
```

The tests and the release gate run against **stand-ins** of the four systems
([`standins/landscape.py`](genai-assistant-service/src/genai_assistant_service/standins/landscape.py)),
which keep their HTTP contracts and guarantees (idempotent adjustments, tenant checks).

| Evidence | What |
|---|---|
| `tests/` | the four journeys; the failure-injection matrix (model down, unknown settlement answer, replayed and concurrent approvals, wrong approver, self-approval, cross-tenant, a settlement changed since the proposal); safety (injection, policy limits, invented identifiers, entitlements, redaction); the API with Cloud Run identity |
| `evals/golden.json` | 53 cases: grounding and citations, tool choice, proposals within and beyond policy, approvals, unsupported and ambiguous requests, unknown identifiers, model and system outages, cross-tenant |
| `evals/redteam.json` | prompt injection in the request and inside a record; personal data in the request |
| CI | tests, a second run with the state in Firestore (emulator), strict E2A conformance, the release gate and its report, Terraform checks, the image with a Trivy scan |

## On Google Cloud (free tier)

| Folder | What |
|---|---|
| [`landscape/foundation`](landscape/foundation) | applied once for the whole landscape: the APIs, one Artifact Registry repository (a cleanup policy keeps it within the free 0.5 GB), the project's one free Firestore database (shared; each service keeps its own collections), a state bucket, GitHub Actions deployment through Workload Identity Federation (no JSON key), a budget alert at the first cent, and the Gemini key's secret (its value is added by hand) |
| [`genai-assistant-service/infra`](genai-assistant-service/infra) | the assistant: Cloud Run scaled to zero with one instance, private (Cloud Run IAM), its state in Firestore, its own Google ID token to the four systems, Gemini's free tier with the key from Secret Manager |
| [`deploy/gcp`](deploy/gcp) | `landscape.vars` (the values every repository shares) and `binding.vars` (the assistant's): placeholders until the account exists; [`landscape/tfvars.py`](landscape/tfvars.py) turns them into one stack's Terraform inputs |

Free-tier limits are enforced by the configuration: Always Free regions only, `simulated` or `gemini_api` models only, never a public service. CI plans both stacks against a mock provider.

## The landscape scenario

[`landscape/scenario.py`](landscape/scenario.py) is the acceptance test of the whole landscape (hub design note GCP-01, Section 7): an order goes through order-to-cash and settlement; settlement's event reaches audit-ai through Pub/Sub, and a large settlement is flagged; a bank statement with a short payment reaches reconciliation, which raises an exception; the assistant explains it with citations to what it read, proposes a write-off, and waits; the investigator cannot approve it, a second person can; one adjustment is in the ledger, which stays balanced; the same request, the same approval and a redelivered event are replayed with no second posting and no second finding; an injection is refused and another tenant reads nothing.

The [`landscape-gcp`](.github/workflows/landscape-gcp.yml) workflow runs it: `target: local` starts the five services from the `main` branch of their repositories in their Google Cloud configuration (state in the Firestore emulator, events through the Pub/Sub emulator, the ledger in PostgreSQL, the assistant behind Cloud Run-style identity); `target: cloud` runs the same steps against the deployed services after the cutover.
